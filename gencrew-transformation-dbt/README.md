# transformation — dbt ELT project (dev)

Generated by GenCrew from the **measured** source model and the client's mapping
sheet. Layers: `raw` → `business` → `reporting` → `kpi`.

| Layer | Materialisation | Contents |
|---|---|---|
| `raw` | view over landed data | source tables exactly as ingested |
| `business` | table | cleansed, standardised, deduplicated, business rules applied |
| `reporting` | table | star schema: 8 dimensions, 6 facts, surrogate keys, Unknown members |
| `kpi` | table | 12 KPI models, one per declared KPI at its grain |

```bash
dbt deps      # installs dbt_utils (surrogate keys)
dbt build     # runs models and their tests together
```

Facts are **incremental with MERGE** where an incremental column was measured;
nothing is ever deleted or truncated, which is a house rule the generated SQL
cannot break.

See `BUSINESS_RULES.md` for exactly which rules were applied and which need a
human, and `KPI_CATALOG.md` for every KPI and how it is calculated.
